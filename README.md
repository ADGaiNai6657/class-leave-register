# 班级请假登记

一个只在这台 Mac 上本地运行的班级花名册请假登记小工具：把花名册里的所有学生平铺成卡片，
双击卡片填写请假理由与是否补假，最后把结果复制到剪贴板，或复制到剪贴板并导出 CSV 到项目根目录。

- 前端：**纯 HTML + CSS + JavaScript**（无框架、无构建步骤）
- 后端：**Node.js 内置模块**（`http` / `fs` / `child_process` / `zlib`）
- 第三方依赖：**零**（`package.json` 的 `dependencies` 为空，不需要 `npm install`）
- 数据流向：**全部在本机**。不联网、不写数据库、关闭程序即丢失本次填写内容

## 一、花名册要求与核对方式

> **本仓库不包含任何真实花名册。** 花名册是你的本地数据，请自己放到应用所在文件夹
> （或其上一级文件夹，或其中的 `花名册/`、`roster/` 子目录）里，应用启动时会自动扫描；
> 也可以用 `node server.js --roster <文件>` 手动指定。仓库的 `.gitignore` 已经排除了
> `*.xls` / `*.xlsx`，避免花名册被误提交。

开发时用一份真实的班级花名册做过完整核对，结论如下（**通用结论，不含任何学生信息**）：

| 项目 | 结果 |
| --- | --- |
| 实际格式 | 旧版 Excel 97-2003（BIFF8 / OLE2 复合文档），由 WPS 生成，不是伪装成 `.xls` 的文本文件 |
| 工作表 | 1 个 |
| 字段 | 第 1 列 `学号`，第 2 列 `姓名`（第 1 行为表头） |
| 姓名列识别 | 通过表头 `姓名` 精确识别（`source: header`），不是猜的 |
| 数据质量 | 无重复姓名、无重复学号、无空姓名、无异常字符 |

核对方式（两条独立路径互相印证，结果完全一致）：

1. 用 LibreOffice 把原文件直接转成 CSV；
2. 用本项目自带的 `.xls` 解析器读取原文件。

两者的姓名、学号与顺序完全相同（测试中用 sha256 摘要锁定了这一基准；换一份花名册时，
相关断言会自动跳过，因此公开仓库里没有花名册也能跑通测试）。

## 二、为什么没有用 Electron / Tauri

先检查了环境再决定（macOS 26.4 / arm64、Node v26.3.0、npm 11.16.0）：

| 方案 | 实测结论 |
| --- | --- |
| Tauri | 需要 Rust 工具链，本机没有 `rustc`/`cargo`，需额外安装整套工具链 |
| Electron | 本体可安装，但二进制要从 GitHub Releases 下载。实测下载速度约 **86 KB/s**（约 100MB+ 需 20 分钟以上），且 npm 全局缓存目录 `~/.npm` 在当前受限环境下不可写 |
| **Node 内置模块 + 本地浏览器窗口（本项目采用）** | **零依赖、秒级启动**；Node 26 内置 `http`、`zlib`、`TextDecoder`、`fetch`，自带 `pbcopy`/`open` 可调用，足够完成全部需求 |

因此本应用的做法是：一个只监听 `127.0.0.1` 的本地小程序负责「读花名册 / 写剪贴板 / 写 CSV」，
界面仍然是标准的 HTML + CSS + JavaScript，用**系统默认浏览器**打开（不锁定任何浏览器）。
这样既满足了「前端必须是 HTML + CSS + JavaScript」，也没有引入任何大型运行时。

如果以后确实需要打包成 `.app`，第六节给了可选方案。

## 四、如何启动

**方式一：双击启动（推荐）**

在访达中双击 `启动班级请假登记.command`。
会弹出一个终端窗口并自动用**系统默认浏览器**打开界面（不指定、也不依赖 Chrome）。关闭终端窗口即退出程序。

> 首次双击若提示“无法打开，因为来自身份不明的开发者”，右键该文件 → 打开 → 打开即可。

**方式二：命令行**

```bash
cd 班级请假登记
npm start          # 等价于 node server.js
```

**可用参数**

```bash
node server.js --roster ../某花名册.xlsx   # 手动指定花名册
node server.js --port 8080                # 指定端口（默认自动选空闲端口）
node server.js --export-dir ~/Documents    # 指定导出目录（默认项目根目录）
node server.js --title 本某某班            # 指定导出文本首行标题（默认取 local-config.json，否则为本班请假登记）
node server.js --no-open                   # 只启动服务，不自动打开窗口
```

服务只监听 `127.0.0.1`，局域网内的其他设备访问不到（已实测：本机可访问，局域网 IP 连接被拒绝）。

## 五、使用说明

1. **卡片网格**：启动后按花名册顺序平铺所有学生，姓名直接来自花名册文件，没有写死。
2. **卡片大小**：右上角 `卡片大小：小 / 中 / 大`，切换后卡片尺寸和同屏人数立即变化
   （用 `grid-template-columns: repeat(auto-fill, minmax(...))` 实现响应式重排）。
3. **双击卡片**：向下展开，出现「请假理由」文本框（占位提示：`请填入请假理由……`）和「是否补假？」的
   是 / 否单选按钮。再次双击卡片空白处（或点右下角「收起」）即可收起，**已填内容不会丢失**，可以继续修改。
4. **编辑状态**：填写过的卡片会变成浅绿色、右上角显示「已填写」小标签，并在姓名下方显示一行摘要
   （如 `身体不适，需要休息 · 补假：否`）；底部状态栏显示 `已填写 N / 34`。
5. **导出**：点右上角「导出」，弹出浮窗，两个选项：
   - **复制到剪切板**：生成 Tab 分隔的文本（首行标题，次行表头 `姓名 请假理由 是否补假`），可直接粘贴到聊天窗口，
     粘到 Excel / Numbers / WPS 会自动分列。字段内部的换行与制表符会被归一为空格，避免破坏行列结构。
   - **复制到剪切板，并输出 CSV**：同时写剪贴板，并在项目根目录（本文件夹）生成
     `请假登记-年月日-时分秒.csv`（UTF-8 带 BOM、CRLF 换行，Excel / Numbers 打开中文不乱码）。
     成功后浮窗会显示完整路径，并提供「在访达中显示」。
     重复导出不会覆盖旧文件，而是生成带序号的新文件。
6. **导出范围**：**只保留请假的学生**。判定标准与界面上的「已填写」一致 ——
   *填了请假理由* 或 *选择了是否补假*，满足其一即导出；一个人都没填时，导出内容只有标题和表头
   （此时「复制到剪切板」会给出明确提示，不会静默失败）。没有选择「是否补假」时该字段为空，不会替你编造“否”。
7. **首行标题**：剪贴板文本与 CSV 文件的**第一行都是标题**，第二行才是表头，之后是学生数据。
   取值顺序是：`--title` 参数 → 环境变量 `CLASS_LEAVE_TITLE` → 本地配置 `local-config.json`
   → 中性默认值 `本班请假登记`。

   **真实班级名请只写在你本地的 `local-config.json` 里**（该文件已被 `.gitignore` 排除，不会进入版本库；
   格式见 `local-config.example.json`）：

   ```json
   { "title": "本某某班" }
   ```

   这样双击启动也能直接得到你自己的班级标题，而仓库里不留任何班级信息。

   实际导出示例（剪切板文本，`→` 表示 Tab；标题与姓名均为虚构）：

   ```text
   本某某班
   姓名→请假理由→是否补假
   张三→身体不适，需要休息→否
   李四→参加考试，需要"提前"离校 并复诊→是
   ```

   对应的 CSV（Excel / Numbers 打开后第一行为标题，第二行为表头）：

   ```csv
   本某某班
   姓名,请假理由,是否补假
   张三,身体不适，需要休息,否
   李四,"参加考试，需要""提前""离校
   并复诊",是
   ```

8. **关闭程序**：直接关闭终端窗口。本次填写的内容只存在内存里，不会留下任何持久化数据
   （已实测：`localStorage` / `sessionStorage` / `cookie` 均为空，刷新页面即回到初始状态）。

## 六、如何构建 / 打包（可选）

当前无需构建：改完 `web/` 下的文件刷新页面即可，`node_modules` 是空的。

如果需要打包成可以放进「应用程序」文件夹的 `.app`，可选装 Electron（本项目代码**无需改动**，
`server.js` 仍是后端，只要把窗口指向 `http://127.0.0.1:<port>` 即可）：

```bash
cd 班级请假登记
npm install --save-dev electron @electron/packager
```

然后用 Electron 主进程启动内置服务、创建 `BrowserWindow` 指向本地地址，最后：

```bash
npx @electron/packager . 班级请假登记 --platform=darwin --arch=arm64 --overwrite
```

请注意：Electron 会引入约 200MB 的运行时，而且本机实测从 GitHub 下载二进制很慢（约 86 KB/s），
因此**默认不这么做**。

## 八、安全与隐私

- 花名册**只读**：本应用从不修改、移动或删除花名册文件；
- **不出网**：代码里没有任何 `fetch`/`http` 客户端请求外部地址；服务只监听 `127.0.0.1`；
  端到端测试抓取了页面的全部网络请求，确认只访问本机服务；
- **无遥测**：没有埋点、统计、日志上报；控制台只打印本机运行状态；
- **不落盘**：填写内容只在内存；唯一的写文件动作是「导出 CSV」且**只由用户点击触发**，
  目录固定为项目根目录（`班级请假登记/`，可用 `--export-dir` 显式更改），导出的 CSV 已被 `.gitignore` 排除；
- 「在访达中显示」只允许打开导出目录内的文件；
- 页面对所有来自花名册的文字都用 `textContent` 写入，不会执行任何文件里的内容；
- 界面启用了 CSP（`default-src 'self'`）并关闭 `nosniff`/`frame-ancestors` 等风险面。

## 九、异常处理（都不静默）

| 情况 | 表现 |
| --- | --- |
| 找不到花名册 | 顶部红色提示，列出所有搜索目录，并提供「重新扫描花名册」 |
| 找到多个像花名册的文件 | 明确列出候选，界面给出「使用 xxx（N 人）」按钮让你选，绝不擅自猜测 |
| 格式无法解析 | 提示具体原因（例如扩展名是 `.xls` 但内容不是旧版 Excel，建议另存为 `.xlsx` 或 `.csv`） |
| 找不到姓名列 | 提示无法识别，并说明请在花名册中把姓名列标题写成「姓名」 |
| 没有表头但能识别姓名列 | 正常显示，同时在顶部给出「已自动识别第 N 列为姓名列，请核对」的提示 |
| 空姓名 / 重复姓名 | 空姓名行跳过并在顶部提示；重复姓名保留两张卡片并提示 |

| 导出目录不存在 / 无写入权限 | 导出浮窗里显示明确错误（如「没有写入权限，无法导出到：…」） |
| 剪贴板写入失败 | 导出浮窗里显示明确错误（CSV 仍会写出，并单独提示剪贴板失败） |

## 十、支持的花名册格式与识别规则

- **`.xls`**（Excel 97-2003 / BIFF8，含 WPS 生成的文件）：自研最小解析器，支持共享字符串（含 `CONTINUE`
  跨记录）、`LABELSST`/`LABEL`/`RSTRING`/`RK`/`MULRK`/`NUMBER`/`BOOLERR`/`FORMULA` 等记录；
- **`.xlsx`**：自研最小解析器（ZIP + XML，用内置 `zlib` 解压），支持共享字符串、富文本、`inlineStr`、数字；
- **`.csv` / `.tsv` / `.txt`**：自动嗅探分隔符（`,` `TAB` `;` `|`），支持 RFC4180 引号转义与字段内换行；
- **`.json`**：对象数组（含 `姓名` 字段）或字符串数组；
- **编码**：UTF-8（含 BOM）、GBK、UTF-16LE 自动识别。

姓名列定位顺序：① 在前 12 行中找标题为 `姓名 / 名字 / 学生姓名 / name` 的列 →
② 若没有表头，则按「像姓名的比例、唯一性」自动识别并明确提示 →
③ 仍然无法可靠判断时报错，不猜。

## 十一、已知问题与限制

1. 界面语言、数字格式等按中文班级场景设计，未做多语言。
2. 花名册人数上限保护为 5000 人（超出会拒绝解析，避免误读大表）。
3. `.xls` / `.xlsx` 解析器是「最小实现」，只覆盖花名册这类简单表格：
   不支持宏、图表、合并单元格语义、公式计算（只读取单元格里已存的值）；
   若某个 `.xls` 结构特殊导致读取失败，请用 Excel/WPS/Numbers 另存为 `.xlsx` 或 `.csv` 后重试。
4. `.xlsx` 不支持 ZIP64（超大工作簿），同样建议另存为 `.csv`。
5. 填写内容不做持久化（按需求刻意如此），关闭窗口即丢失；也没有“撤销/重做”。
6. 卡片大小与窗口状态不记忆，每次启动都是「中」号。
7. 若同一文件夹里同时放了多个花名册文件，每次启动都需要手动点选一次（不会记忆选择）。
8. 应用用系统默认浏览器打开界面（没有独立的 App 窗口，就是浏览器里的一个标签页）；
   如需「应用窗口」外观，可自行改装 Electron（见第六节）。

## 十二、版本管理（git）

本目录（`班级请假登记/`）本身就是一个 git 仓库，默认分支 `main`：

```bash
git log --oneline        # 查看提交
git status               # 查看改动
```

**刻意不纳入版本库的内容**（见 `.gitignore`）：

| 排除项 | 原因 |
| --- | --- |
| `.DS_Store`、`._*` | macOS 自动生成的系统文件，与项目无关 |

| `.idea/`、`.vscode/` | 编辑器 / IDE 的本地配置 |

也就是说：**版本库里只有程序代码、测试和文档，没有任何真实学生个人信息。**
